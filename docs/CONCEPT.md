# tganki — концепция Telegram-бота для изучения слов по карточкам

Статус: черновик концепции. Ниже — продуктовые решения, архитектура, алгоритм и монетизация.
Спорные места помечены как «решение» с обоснованием, чтобы их можно было оспорить до начала кода.

---

## 1. Суть продукта

Anki для людей, которые не готовы ставить Anki. Весь цикл — добавить слово, повторить, получить напоминание —
происходит внутри Telegram, без установки приложений и синхронизации.

**Позиционирование относительно конкурентов**

| Конкурент | Их слабость | Наш ответ |
|---|---|---|
| Anki | Высокий порог входа, уродливый мобильный UX, платный iOS-клиент | Нулевая настройка, карточка приходит как сообщение |
| Duolingo / Memrise | Чужая программа, нельзя учить «свои» слова | Свои слова из своих текстов, AI заполняет обратную сторону |
| Quizlet | Нет нормального интервального повторения, дорогой | FSRS из коробки, дешевле |
| Существующие TG-боты для слов | Обычно один язык, SM-2 или без алгоритма, нет импорта | Любые языковые пары, FSRS, импорт из Anki/CSV/фото/ссылки |

**Ключевые дифференциаторы** (в порядке приоритета):
1. Скорость добавления слова: переслал сообщение или написал слово — через 2 секунды карточка готова (перевод, транскрипция, пример, аудио — генерируются).
2. FSRS вместо SM-2 — заметно меньше повторений при той же запоминаемости.
3. Социальность Telegram: делиться деками ссылкой, деки в группах, режим «преподаватель → ученики».

## 2. Пользовательский опыт в Telegram

### 2.1. Основной цикл повторения

Один экран = одно сообщение, которое бот **редактирует на месте** (`editMessageText`), а не шлёт новое.
Иначе чат превращается в простыню и юзер уходит.

```
┌──────────────────────────────┐
│ 🇬🇧 EN → RU  · Дека: Top 1000 │
│                              │
│   reluctant                  │
│   /rɪˈlʌktənt/               │
│                              │
│   12 / 25         🔥 7 дней   │
├──────────────────────────────┤
│ [ 👁 Показать ответ ]         │
│ [ 🔊 ]  [ ✏️ ]  [ ⏸ Стоп ]   │
└──────────────────────────────┘
        ↓ тап
┌──────────────────────────────┐
│   reluctant                  │
│   ───────────                │
│   неохотный, сопротивляющийся│
│   _She was reluctant to go._ │
├──────────────────────────────┤
│ [ Снова ] [ Трудно ] [ Хорошо ] [ Легко ] │
│   <1м      6м        1д        4д        │
└──────────────────────────────┘
```

- Четыре оценки как в Anki, с подписью интервала под каждой — это заметно влияет на качество оценок.
- Кнопка «Отменить последнюю оценку» (`/undo`) — обязательна, промахи по кнопкам в Telegram частые.
- Сессия = до N карточек (по умолчанию 20 повторений + 10 новых). В конце — итог и следующий срок.

### 2.2. Режимы карточек

| Режим | Как выглядит | Когда |
|---|---|---|
| Recognition | слово → перевод | по умолчанию |
| Recall | перевод → слово | включается на деку |
| Multiple choice | 4 варианта, дистракторы из той же деки | для новых слов, снижает трение |
| Typed | пользователь пишет слово текстом, бот сравнивает с учётом опечаток | Pro, для «активного» словаря |
| Audio | голосовое сообщение (TTS) → перевод | для аудирования, Pro |

Решение: MVP — только Recognition + Recall. Остальное после подтверждения retention.

### 2.3. Добавление слов

Порядок по частоте использования:
1. **Просто написать слово в чат.** Бот отвечает превью карточки (перевод, транскрипция, пример) и кнопками
   «Добавить в …» / «Исправить». Попадает в деку «Входящие» или в последнюю активную.
2. **Переслать сообщение / вставить текст / ссылку.** Бот выделяет слова выше уровня пользователя,
   показывает список с чекбоксами. Это «убийца» фичи — учить слова из того, что реально читаешь.
3. **Фото** (страница книги, меню) → OCR → тот же список.
4. **Импорт файла**: CSV/TSV, `.apkg` (Anki — это zip с SQLite, парсится штатно), Quizlet-экспорт.
5. Ручное создание через Mini App (форма с полями).

### 2.4. Где бот, а где Mini App

Решение: **бот — для повторений и быстрого добавления, Mini App — для всего, где нужны списки и формы**
(каталог дек, редактор деки, статистика с графиками, настройки, оплата).
Повторять в Mini App хуже: нет push через Telegram, дольше открывается. Каталог из 50 дек инлайн-кнопками — пытка.

### 2.5. Напоминания и удержание

- Ежедневное уведомление в выбранное время: «У тебя 23 карточки на сегодня · ~6 минут». Одно, не три.
- Таймзона: Telegram её не отдаёт. Берём из Mini App (`Intl.DateTimeFormat().resolvedOptions().timeZone`)
  при первом открытии, до этого — спрашиваем в онбординге город/смещение.
- Стрик с «заморозкой» (1 пропуск в неделю не сбрасывает). Стрик — главный рычаг retention у Duolingo, копируем.
- Еженедельный отчёт: выучено / повторено / точность.

### 2.6. Команды

`/start` онбординг · `/learn` начать сессию · `/add` добавить · `/decks` мои деки · `/stats` · `/settings` · `/undo` · `/pro`

Плюс inline-режим `@tganki_bot word` — вставить карточку в любой чат (вирусный канал).

## 3. Деки

### 3.1. Модель данных (как в Anki: заметка ≠ карточка)

```
Note      — единица контента: front, back, transcription, example, example_translation,
            audio_file_id, image_file_id, tags, lang_from, lang_to
Card      — Note × направление (recognition | recall | typed …) + состояние FSRS
Deck      — набор Note; тип: builtin | user | shared
UserDeck  — подписка пользователя на деку + личные настройки (лимиты, режимы)
```

Ключевое следствие: **встроенные деки хранятся один раз**, у пользователя — только его прогресс по карточкам.
Пользователь может «форкнуть» встроенную деку в свою и править.

### 3.2. Готовые деки

Первая волна (под русскоязычную аудиторию, потом расширяем):

- Английский по частотности: Top 500 / 1000 / 3000 / 5000, разбитые по CEFR A1–C1.
- Тематические: путешествия, IT/работа, бизнес-переписка, медицина, еда.
- Экзаменационные: IELTS Academic, TOEFL — платные.
- Немецкий, испанский, французский, итальянский — Top 1000 + A1/A2.
- Грузинский — алфавит (33 буквы со звуками), Top 500 A1, A2. Особенности: глаголы даём через масдар, транскрипция IPA с пометкой абруптивных.
- Далее по спросу: китайский HSK 1–4, японский JLPT N5–N3, корейский, турецкий, арабский.

**Источники и лицензии** — самая недооценённая часть:
- Частотные списки: OpenSubtitles-based (CC BY-SA), Wiktionary/Kaikki (CC BY-SA), собственная генерация.
- Переводы, примеры, транскрипции — генерируем LLM один раз, ревьюим, кэшируем. Своё — без лицензионных рисков.
- Не тащить чужие Anki-shared-decks: лицензии там хаотичные, авторы регулярно жалуются.
- Аудио: TTS (см. §5), файлы заливаем в Telegram один раз и переиспользуем `file_id` — бесплатный CDN.

### 3.3. Пользовательские деки

- Создать, переименовать, удалить, объединить, экспорт в CSV/`.apkg` (юзер должен уметь уйти — это доверие).
- Публичная ссылка на деку `t.me/tganki_bot?start=deck_XXXX` — подписка одним тапом.
- **Маркетплейс** (этап 2): авторы публикуют деки, бесплатно или за Stars, revenue share 70/30.
  Модерация обязательна: контент, дубликаты, авторские права.

### 3.4. Режим преподавателя (этап 2)

Учитель создаёт класс → ученики входят по ссылке → учитель назначает деки, видит прогресс каждого.
Это самый прямой путь к деньгам (см. §6): репетиторы и языковые школы в СНГ, Турции, Иране, Бразилии живут в Telegram.

## 4. Языки

Два независимых измерения:

1. **Язык интерфейса.** Берём из `User.language_code`, даём переключить. Старт: ru, en, uk. Потом: es, pt-BR, tr, de, fa, id.
   Все строки — через i18n с плюрализацией (в русском три формы: «1 карточка / 2 карточки / 5 карточек»).
2. **Языковая пара обучения.** Любая `lang_from → lang_to`, у пользователя может быть несколько.
   Генерация карточек не зависит от пары — LLM справляется с любой. Ограничения только у TTS и OCR.

Особенности по письменностям:
- RTL (арабский, иврит, фарси) — Telegram рендерит сам, но в inline-кнопках с направлением бывают артефакты, тестировать.
- CJK — нужны поля для чтения (пиньинь, фуригана/кана), это отдельные поля Note, не хак в `transcription`.
- Транскрипция: IPA по умолчанию; для китайского — пиньинь, для японского — кана.

## 5. Алгоритм повторения

### Решение: FSRS, не SM-2

- FSRS (Free Spaced Repetition Scheduler) — дефолт в Anki с версии 23.10, открытый, по бенчмаркам даёт на 20–30 % меньше повторений при той же вероятности вспоминания, чем SM-2.
- Готовые библиотеки: `fsrs` (PyPI, py-fsrs) и `ts-fsrs` (npm). Написать своё поверх SM-2 не быстрее.
- Главный параметр для пользователя один — **желаемая запоминаемость** (по умолчанию 0.9). Всё остальное скрыто.

**Что храним на карточку:** `stability`, `difficulty`, `due`, `last_review`, `reps`, `lapses`, `state` (new / learning / review / relearning).
**Обязательно храним лог повторений** (`review_log`: card_id, rating, review_at, elapsed_days, scheduled_days, state).
Он нужен для персональной оптимизации весов FSRS (fsrs-optimizer) — это фича Pro, и для отладки.

**Механика сессии:**
- Порядок: сначала просроченные повторения (по дате), потом новые (в порядке деки — частотные списки уже отсортированы по полезности).
- Шаги обучения новой карточки: 1 мин → 10 мин внутри одной сессии, затем FSRS. В Telegram это нормально работает: карточка просто возвращается в очередь текущей сессии.
- Лимиты в день: новых 10 (по умолчанию), повторений — без лимита (лимит на повторения — главная причина «снежного кома» у новичков Anki).
- Leech: 8 «Снова» на карточке → бот предлагает переписать или приостановить.
- «Отложить» карточку (bury) до завтра.

Расписание работает по UTC, показ — в таймзоне пользователя; «день» пользователя начинается в 4:00 по его времени (как в Anki), иначе ночные сессии рвут стрики.

## 6. Монетизация

### 6.1. Платёжный рельс: Telegram Stars

Не выбор, а требование: по правилам Telegram цифровые товары и услуги в ботах продаются только за Stars.
Плюсы, которые из этого выжимаем:
- Работают в РФ и странах, где иностранные карты не проходят. Для нашей первой аудитории это решает.
- Есть **подписки в Stars** (`createInvoiceLink` с `subscription_period = 30 дней`) — рекуррентные платежи без своего биллинга.
- Есть **встроенная партнёрская программа** (Bot API 8.0): каналы и другие боты могут продвигать нас за процент — Telegram сам считает и выплачивает.
- Подарить подписку другу — нативно.

Минусы, которые учитываем в цене:
- Эффективная комиссия ~30–35 % (юзер покупает Stars через App Store/Google Play, мы выводим через Fragment в TON по курсу ниже покупки).
- Вывод: холд 21 день, минимум 1000 Stars. Кассовый разрыв на старте.
- Юзер платит в «звёздах», а не в деньгах, — цена должна выглядеть круглой в Stars, а не в долларах.

### 6.2. Тарифы

| | Free | Pro | Lifetime |
|---|---|---|---|
| Цена | 0 | ~199 Stars/мес (~$4), ~1499/год | ~2999 Stars |
| Повторения | без ограничений | без ограничений | |
| Свои деки / карточки | 3 деки, 300 карточек | без ограничений | |
| Встроенные деки | базовые (Top 1000 и A1–A2) | все, включая экзаменационные | |
| AI-генерация карточки | 5 в день | без ограничений | |
| Добавление из текста / фото / ссылки | 1 текст в день, без фото | да | |
| Импорт `.apkg` / экспорт | экспорт есть, импорт нет | да | |
| Аудио (TTS) | нет | да | |
| Режимы Typed / Audio / Multiple choice | нет | да | |
| Статистика | базовая | графики + прогноз нагрузки | |
| Персональная оптимизация FSRS | нет | да | |
| Напоминания | 1 в день | гибкие | |

Принцип: **повторения бесплатны навсегда**. Платим за контент, генерацию и удобство, а не за право учиться.
Ограничение на повторения убивает продукт — юзер просто перестаёт делать привычку.

Ожидаемая конверсия free→pro в language-learning: 2–5 %. Значит, экономика держится на очень низкой себестоимости free-юзера (см. 6.4).

### 6.3. Дополнительные источники

1. **Платные деки** (разово, 99–499 Stars): экзаменационные, профессиональные, авторские с маркетплейса (70 % автору).
2. **Тариф для преподавателей**: ~499 Stars/мес за класс до 30 учеников; ученикам Pro-функции внутри назначенных дек — бесплатно. Это B2B2C с высокой лояльностью: репетитор не уйдёт, пока ученики в системе.
3. **Партнёрская программа** — не источник, а канал: отдаём 20–30 % с первого платежа тем, кто приводит.
4. **Реферальная**: пригласил друга — обоим неделя Pro.
5. Реклама — **нет**. Рекламная карточка в сессии ломает единственную вещь, за которую нас любят. Максимум — один спонсорский блок в недельном отчёте для free, и только если совсем прижмёт.

### 6.4. Себестоимость и почему это сходится

Основные переменные расходы — LLM и TTS. Оба гасятся кэшированием:
- Генерацию (перевод + транскрипция + пример) для пары `(слово, lang_from, lang_to)` делаем **один раз на всех**. Словарь Top 5000 закрывает ~90 % запросов после первых сотен пользователей. Реальная стоимость — доли цента на слово, один раз.
- TTS — то же самое, плюс `file_id` Telegram: аудио хранится у них.
- Инфраструктура: один сервис + Postgres + Redis. До 50–100 тыс. пользователей — десятки долларов в месяц.

Себестоимость free-юзера стремится к нулю, поэтому 3 % конверсии достаточно.

### 6.5. Порядок включения монетизации

1. Запуск полностью бесплатным на 1–2 месяца — собрать retention и понять, за что просят заплатить.
2. Включить Pro, когда D7 retention > 20 % и есть 1000+ WAU. Раньше — бессмысленно, только шум.
3. Преподавательский тариф — после того, как первые репетиторы сами начнут просить «посмотреть прогресс ученика» (они начнут).

## 7. Архитектура

### 7.1. Стек (решение)

- **Node 22 + TypeScript (strict, ESM) + pnpm.**
- **grammY** — самый зрелый TS-фреймворк для Telegram: типизированный Bot API, middleware, `@grammyjs/i18n` для локализации, webhook-адаптеры.
- **ts-fsrs** — официальный TS-порт FSRS от open-spaced-repetition; персональная оптимизация весов (этап 3) — через отдельный Python-воркер с fsrs-optimizer, он на ядро не влияет.
- **PostgreSQL + Drizzle ORM** (postgres.js, миграции drizzle-kit). Без Redis в MVP: состояние сессии и очередь напоминаний живут в Postgres, один процесс. Redis добавим, когда упрёмся.
- **Hono** — HTTP-слой: webhook Telegram, healthcheck, позже статика и API Mini App.
- **Планировщик** напоминаний: крон внутри процесса (раз в минуту выбирает пользователей, у кого наступило время), отправка через очередь с троттлингом.
- **LLM** для генерации карточек — этап 2 (в MVP отключено из-за стоимости). Контракт зафиксирован в `src/llm/types.ts`; реализация — Anthropic Claude через официальный SDK с кэшем в Postgres (`generated_cache`).
- **TTS**: облачный TTS с нейроголосами, результат — OGG/Opus для голосовых сообщений (этап 2).
- **Mini App** (этап 2): React + Vite, статика на том же домене через Hono; авторизация через проверку `initData` (HMAC от bot token).
- **Деплой**: Railway (сервис + Postgres), Dockerfile, webhook на публичный домен Railway. Миграции применяются на старте контейнера.
- Тесты: vitest — алгоритм, очередь сессии и парсеры покрываем в первую очередь. Линт/формат: Biome.

### 7.2. Схема данных (первое приближение)

```
users            id, tg_id, ui_lang, tz, daily_new_limit, reminder_time, plan, plan_until, streak, created_at
decks            id, owner_id (null=builtin), title, lang_from, lang_to, kind, is_public, price_stars
notes            id, deck_id, front, back, transcription, example, example_tr, audio_file_id, image_file_id, tags[]
cards            id, note_id, user_id, mode, state, stability, difficulty, due, last_review, reps, lapses, suspended
review_logs      id, card_id, user_id, rating, reviewed_at, elapsed_days, scheduled_days, state_before
user_decks       user_id, deck_id, new_per_day, modes[], added_at
generated_cache  key(word, lang_from, lang_to, kind), payload jsonb, created_at
payments         id, user_id, tg_charge_id, stars, product, subscription_expires_at, created_at
```

`cards` создаются лениво: при подписке на деку из 5000 слов не плодим 5000 строк, а создаём карточку в момент,
когда она впервые попадает в очередь как новая.

### 7.3. Ограничения Telegram, о которые бьются все

- Лимиты: ~30 сообщений/сек на бота суммарно, 1/сек в один чат, 20/мин в группу. Рассылка напоминаний — через очередь с троттлингом, не циклом.
- `editMessageText` не может превратить текст в голосовое: для аудио-карточек шлём отдельное голосовое и удаляем его после ответа.
- Callback data ≤ 64 байта — кладём короткие id, не JSON.
- Сообщение старше 48 часов нельзя редактировать — незавершённую сессию после этого срока начинаем заново.
- Бот не знает таймзону и не может «дозвониться», если пользователь его заблокировал — считать блокировки метрикой оттока.

## 8. План: MVP и дальше

### MVP (цель — 4–6 недель, один разработчик)

1. Онбординг: язык интерфейса → языковая пара → стартовая дека → время напоминания.
2. Цикл повторения на FSRS: recognition + recall, 4 оценки, undo, итог сессии.
3. 5 встроенных дек: EN Top 1000 по A1–B1 для русскоязычных + Top 500 DE/ES.
4. Добавление слова текстом с AI-заполнением, дека «Входящие», простые свои деки.
5. Ежедневное напоминание, стрик.
6. `/stats` текстом: выучено, на сегодня, точность за неделю, прогноз на 7 дней.
7. Минимальная аналитика событий (старт, сессия, добавление, отток) — без неё нельзя принимать решение по монетизации.

### Этап 2 (после подтверждения retention)

Mini App (каталог, редактор, статистика) · Pro через Stars · импорт `.apkg`/CSV · добавление из текста и ссылки · TTS · Multiple choice и Typed · экспорт.

### Этап 3

Маркетплейс дек · режим преподавателя · персональная оптимизация FSRS · фото/OCR · партнёрская программа · новые языки интерфейса.

## 9. Метрики, по которым решаем, живёт ли продукт

| Метрика | Порог для перехода к монетизации |
|---|---|
| Онбординг → первая сессия | > 60 % |
| D1 / D7 / D30 retention | > 40 % / > 20 % / > 10 % |
| Средняя сессия | 3–8 минут (дольше — устают, короче — не учат) |
| Доля дней с сессией у активных | > 50 % |
| Добавлено своих карточек на юзера за первую неделю | > 10 (сигнал, что нужны именно свои слова) |

## 10. Риски

- **Низкая готовность платить** за изучение слов. Ответ: преподавательский тариф и платные деки как второй и третий рычаг, а не только подписка.
- **Зависимость от одной платформы.** Бан бота или смена правил Stars = ноль. Ответ: экспорт данных, email/аккаунт пользователя в Mini App как запасной идентификатор, данные хранить так, чтобы за неделю поднять веб-версию.
- **Качество AI-генерации** для редких пар языков. Ответ: кнопка «Исправить» с первого дня + ревью сгенерированного для встроенных дек человеком.
- **Лицензии на контент.** Ответ: только открытые списки и собственная генерация, см. §3.2.
- **Копируемость.** Бот с FSRS сделает любой за месяц. Защита — контент (деки), сообщество авторов, преподаватели с классами. Не код.
